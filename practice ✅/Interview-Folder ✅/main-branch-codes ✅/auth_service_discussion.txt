🔷 Interviewer Question 1:
“Explain this register_user() function flow”
✅ Expected Answer (Points Format)
1.	This function handles business logic for user registration. 
2.	It separates controller/routes from database operations. 
3.	Creates a new User object using SQLAlchemy ORM. 
4.	Password is hashed using set_password() before storing. 
5.	User data is added using db.session.add(). 
6.	Changes are permanently stored using db.session.commit(). 
7.	Logging is added for request tracing using request_id. 
8.	Duplicate email handling is managed using IntegrityError. 
9.	Database rollback is done to maintain consistency. 
10.	Function returns proper JSON response with HTTP status codes.

🔷 Interviewer Question 4:
“Why use try-except with IntegrityError?”
✅ Expected Answer
1.	Handles duplicate entries safely. 
2.	Prevents application crash. 
3.	Gives user-friendly API response. 
4.	Helps maintain DB consistency. 
5.	Used for unique constraint violations like duplicate email. 
________________________________________
🔷 Interviewer Question 5:
“Why rollback after exception?”
✅ Expected Answer
1.	SQLAlchemy session enters failed state after exception. 
2.	Rollback resets transaction. 
3.	Prevents partial/inconsistent DB commits. 
4.	Ensures atomic transaction handling. 
________________________________________

🔷 Interviewer Question 7:
“Why hash password before storing?”
✅ Expected Answer
1.	Plain passwords should never be stored. 
2.	Hashing improves security. 
3.	Even DB leaks won't expose actual passwords. 
4.	Usually implemented using bcrypt/werkzeug security.
